## MongoDB collections

I would keep the database modular rather than putting everything into one `users` collection:

```text
users
students
sessions
conversations
messages
plans
subscriptions
payments
transactions
usage
notifications
admin_logs
webhook_events
```

The **webhook_events** collection is particularly useful because payment webhooks can sometimes be delivered more than once. You can store the gateway event ID and prevent duplicate processing.

### One important architectural decision

Keep these three things separate:

**Payment**

```text
Did money move?
```

**Subscription**

```text
Does this user currently have access?
```

**Usage**

```text
How much has this user consumed?
```

That separation will make the project much easier to maintain.

For a 60-day build, I would also avoid trying to build every possible feature immediately. **Days 1–41 establish the platform, Days 42–51 make the LM experience complete, Days 52–60 make it production-ready.** This gives you a functioning MVP well before Day 60 rather than discovering integration problems at the end.
